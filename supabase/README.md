# Реальный режим: Supabase + Google (всё бесплатно)

> Статус: **вход через Google для мастеров настроен**; синхронизация с Google Calendar отложена (см. шаг 5). **Шаг 1 сделан** (проект «Barbershop», схема и патчи `patch-1.sql`, `patch-2.sql`, `patch-3.sql` применены (телефон обязателен, почта и Telegram по желанию), публичный ключ в `assets/config.js`). Осталось: вход через Google (шаг 2), почты мастеров, затем синхронизация календаря (шаг 5).

Пока на сайте работает **демо-режим**: записи хранятся в браузере. Чтобы записи стали общими для всех
устройств, мастера входили через Google, а записи попадали в Google Calendar, нужно один раз настроить
два бесплатных сервиса. Ничего платного здесь нет. Секретные ключи в чат и в репозиторий не вставляйте.

## 1. Supabase (база и вход)
1. Зайдите на supabase.com → создайте проект (бесплатный тариф, регион ближе к Израилю — например Frankfurt).
2. **SQL Editor** → вставьте весь файл `supabase/schema.sql` → **Run**.
3. **Project Settings → API**: скопируйте `Project URL` и ключ `anon public`. Они публичные по замыслу Supabase,
   их можно вписать в `assets/config.js`:
   ```js
   own: { supabaseUrl: "https://XXXX.supabase.co", anonKey: "eyJ..." },
   ```
   Ключ `service_role` никому не отправляйте и в код не вставляйте.
4. **Table Editor → staff**: впишите в колонку `email` настоящие Google-почты Димы, Таши и Кирилла.
   При первом входе каждый мастер автоматически привязывается к своему профилю по этой почте.

## 2. Вход через Google
1. console.cloud.google.com → новый проект → **APIs & Services → OAuth consent screen** (тип External, название «GRIND»).
   Нужны только базовые данные (почта и имя), поэтому проверка Google не требуется.
2. **Credentials → Create credentials → OAuth client ID → Web application**.
   В «Authorized redirect URIs» вставьте адрес из Supabase: **Authentication → Providers → Google → Callback URL**.
3. Скопируйте Client ID и Client secret в Supabase: **Authentication → Providers → Google → Enable**.
4. **Authentication → URL Configuration**: Site URL = адрес сайта, в Redirect URLs добавьте адреса страниц
   `/staff/` и `/my/` (например `https://egorchet.github.io/barbershop-netanya/staff/`).

После этого страница `/staff/` покажет кнопку «Войти через Google», а `/my/` позволит клиентам видеть свои записи.

## 3. Что умеет кабинет мастера (`/staff/`)
Календарь дня и недели, новая запись, перенос, правка, отмена и удаление, закрытие времени (обед, врач),
часы работы по дням. Двойную запись блокирует сама база (`no_double_booking`).

## 4. Приватность
Клиенты не видят чужих записей: сайт получает только занятые интервалы без имён и телефонов (функция `busy`).
Мастер видит только свои записи. Клиент видит только свои.

## 5. Ветка на будущее: синхронизация с Google Calendar (СЕЙЧАС ВЫКЛЮЧЕНА)

> Решение: пока записи живут только в базе и в кабинете `/staff/`. Весь код и схема сохранены (колонки `google_calendar_id`, `gcal_synced`, блок в настройках кабинета), включается флагом `own.googleCalendar: true` в `assets/config.js`. Вход мастеров через Google при этом остаётся как есть.

Идея: **сервисный аккаунт Google** (бесплатный, без проверки приложения и без «протухающих» токенов).
Каждый мастер один раз открывает доступ к своему календарю для почты сервисного аккаунта с правом
«Вносить изменения в мероприятия». Дальше сервер (Supabase Edge Function, бесплатно):
- при создании, переносе или отмене записи создаёт, двигает или удаляет событие в календаре мастера;
- читает занятость календаря (free/busy) и закрывает это время на сайте, то есть синхронизация двусторонняя
  по времени, а личные встречи мастера не пересекутся с клиентами.

Для этого шага (когда вернёмся к нему) понадобится JSON-ключ сервисного аккаунта. Его вы кладёте только в **Supabase → Edge Functions →
Secrets**, в чат его присылать не нужно. Функции (`gcal-sync`) напишу, когда шаги 1–2 готовы и я смогу проверить их на живой базе.
